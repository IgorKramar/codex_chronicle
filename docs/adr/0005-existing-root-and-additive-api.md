# ADR 0005: готовый Notion root и расширение API без миграции истории

Статус: Accepted. Дата: 2026-10-19.

Проблема: есть готовая пользовательская страница Observatory, а прежний NOTION_PARENT означал страницу-контейнер. Кроме того, внешним агентам требуются отдельная запись тестов/знаний и сводки.

Решение: новый NOTION_PARENT_PAGE_ID / CLI --root явно выбирает существующий корень. Publisher проверяет доступ и title, добавляет дочерние базы, не изменяет пользовательские блоки. Старый --parent / NOTION_PARENT сохраняет прежнее поведение. Секрет поступает из private file/env, не из connector ChatGPT.

REST/MCP используют то же независимое MemoryService, тот же ledger и модель полномочий. Новые операции добавляются без изменения форм ранее опубликованных сущностей и без переписывания legacy событий. Отдельный ExtendedQueuedWriteResponse сохраняет старый закрытый enum QueuedWriteResponse.

Альтернативы: создать второй Observatory (дублирует пространство), заменить значение старой настройки (ломает установки), переписать контракт v1 (ломает strict clients). Отклонены.

Последствия: оба режима root документируются отдельно. Живой Notion требует dedicated integration. Модель доверия не меняется: данные журналов не являются командами; успешный тест требует завершённого выполнения и согласованного exit_code. Работа ядра и API продолжается без Notion.
