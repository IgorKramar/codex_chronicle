# Подключение существующего Notion Observatory

Корень уже существует: [CODEX CHRONICLE — Development Observatory](https://app.notion.com/p/3fe99aa2eb7b815ba30ed0a315146484), ID `3fe99aa2-eb7b-815b-a30e-d0a315146484`. Чтение через ChatGPT проверено 2026-10-19; это **не** проверка доступа отдельной интеграции Publisher. На странице находятся заголовки и пояснения, а не базы данных.

## Отдельная интеграция

1. Откройте https://www.notion.so/profile/integrations и создайте внутреннюю интеграцию Chronicler для нужного workspace. Достаточны Read content, Insert content, Update content; доступ к пользователям и комментариям не требуется.
2. В меню существующей страницы выберите Connections / Add connections, подключите интеграцию. Если она не видна, проверьте workspace, права владельца страницы и политику администратора workspace. Дочерние базы должны наследовать доступ.
3. Выполните команды в **своём локальном терминале**, не в переписке:

```bash
chronicle init
chronicle notion --root 3fe99aa2-eb7b-815b-a30e-d0a315146484
chronicle notion --set-token
chronicle notion --check
```

`--set-token` использует скрытый ввод getpass; создаёт новый файл `~/.chronicle/secrets/notion_token` с mode 600. Значение не выводится и не входит в config.json. На Windows дополнительно ограничьте ACL файла своей учётной записью через Properties → Security. При повторной настройке команда откажется перезаписывать файл: сначала сохраните новый токен в новом закрытом файле, задайте `NOTION_TOKEN_FILE`, проверьте доступ, отзовите прежний токен в Notion и удалите старый файл.

Для сервера / контейнера используйте секретный файл вне checkout и переменные:

```bash
export NOTION_PARENT_PAGE_ID=3fe99aa2-eb7b-815b-a30e-d0a315146484
export NOTION_TOKEN_FILE=/private/chronicle/notion_token
export CHRONICLE_NOTION_PROJECTS=AUTHORIZED_PROJECT_ID
```

`NOTION_PARENT_PAGE_ID` означает **готовый корень**. Старый `NOTION_PARENT` сохраняет прежнюю семантику контейнера, внутри которого Publisher ищет/создаёт корень. Не используйте старый параметр для этой страницы. `NOTION_TOKEN` также поддерживается для secret managers. Файл токена с групповым/общим доступом на Unix отвергается.

## Проверка записи

Сначала выполните read-only `--check`. HTTP 401 — токен не принят; 403 — недостаточные capabilities; 404 — проверьте ID, workspace и подключение интеграции к странице (Notion может скрывать отсутствие прав за 404). Успешное чтение не доказывает право записи.

Разрешите экспорт только синтетического тестового проекта. Затем запустите явный live-тест:

```bash
export CHRONICLE_LIVE_NOTION=1
pytest -q tests/test_live_notion.py
```

Тест создаёт безопасную запись, читает её блоки, повторяет публикацию, проверяет стабильный page ID и архивирует только записи своего синтетического проекта. Готовый корень и его пользовательские блоки **никогда не архивируются**. Семь дочерних баз создаются либо повторно используются по имени; заголовки и текст корня не редактируются. После теста попросите ChatGPT прочитать возвращённый URL тестовой записи **до очистки** либо выполните обычную публикацию синтетического проекта и чтение через подключённый Notion. Полная приёмка требует проверки этого последнего шага; connector и Publisher имеют разные права.

При неопределённом результате создания Publisher сначала сверяет Chronicle Key. Неопределённое создание без найденной записи требует ручного reconciliation; повторная отправка не создаёт страницу вслепую. `--check` ничего не записывает; `--publish` выполняет реальную публикацию только разрешённых проектов.

Текущее ограничение: dedicated token в этой среде не предоставлен. Подготовка к подключению и mock-тесты выполнены, живая синхронизация не подтверждена.
