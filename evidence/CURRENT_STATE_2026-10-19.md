# Current State: согласование результатов — 2026-10-19

Publisher использует единое представление legacy/FIP вместо склейки двух
независимых сводок. Статус запуска отделён от происхождения. У результата видны
канал legacy/FIP, observed/agent_reported, execution_status, exit_code и source ID.
Наличие agent_reported Passed не выдаётся за observed; последняя ревизия теста
заменяет старый результат сущности `(project_id, test_id)` независимо от автора
и порядка входных записей: выбирается максимальная revision. История остаётся в хранилище.

Реальная проверка на прежних двух синтетических проектах:

- [Проект 0](https://app.notion.com/p/3fe99aa2eb7b81b983badae9d5d5f990):
  `Тесты: agent_reported: Passed — 1`, источник TestResult виден в подробностях.
- [Проект 1](https://app.notion.com/p/3fe99aa2eb7b81359af4df2c63e592e9):
  тестовые результаты не зарегистрированы ни в legacy, ни в FIP.
- Обе страницы обновлены через Publisher, без ручного исправления блоков.
- После повторной публикации ID всех 12 управляемых страниц сохранились;
  у каждого Chronicle Key ровно одна страница.
- Существующий root и исходные пользовательские блоки неизменны.
- Использована копия SQLite только двух синтетических проектов. Рабочие проекты
  не экспортировались; установленный pipx не изменён.

Регрессионные проверки покрывают mixed/FIP-only, Passed/Failed/Unknown,
сохранение provenance, последнюю ревизию и повторную публикацию. Локальные mock
тесты проверяют контракт; реальная публикация проверена отдельно настоящим Notion API.

Приватные evidence.json, токены и логи не включены. Connector readback исходной
приёмки подтверждён владельцем отдельно; чтение обновлённого Current State через
коннектор этим отчётом не заявляется. Остальные критерии stable не меняются.
